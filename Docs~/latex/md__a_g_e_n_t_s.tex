This file is the project\textquotesingle{}s committed home for project-\/intrinsic agent knowledge\+: build, test, release, architecture, and sharp-\/edge notes that should travel with the code.\hypertarget{md__a_g_e_n_t_s_what-this-is}{}\doxysubsection{\texorpdfstring{What this is}{What this is}}\label{md__a_g_e_n_t_s_what-this-is}
{\ttfamily de.\+codesmile.\+assetdatabase} is a Unity editor package sold on the Unity Asset Store and also published here under GPL-\/3.\+0. Public API breakage costs buyers their compile, so treat every signature in {\ttfamily Editor/} as shipped API. {\ttfamily README.\+md} states the supported Unity version range; {\ttfamily package.\+json} {\ttfamily unity} and {\ttfamily unity\+Release} are the machine-\/readable form of it.\hypertarget{md__a_g_e_n_t_s_building-and-testing}{}\doxysubsection{\texorpdfstring{Building and testing}{Building and testing}}\label{md__a_g_e_n_t_s_building-and-testing}
There is no CI that compiles this package\+: {\ttfamily .github/workflows/main.\+yml} only publishes {\ttfamily Docs\texorpdfstring{$\sim$}{\string~}} to Git\+Hub Pages. Compiling and running the tests requires a real Unity editor.

The test suite is {\ttfamily Tests/\+Editor}, an Edit\+Mode NUnit suite that runs in the Unity Test Runner. {\ttfamily Samples\texorpdfstring{$\sim$}{\string~}} is invisible to Unity because of the trailing tilde, so a compile check that only opens the package will not compile the two sample assemblies; copy {\ttfamily Samples\texorpdfstring{$\sim$}{\string~}} into a project\textquotesingle{}s {\ttfamily Assets/} to compile them.\hypertarget{md__a_g_e_n_t_s_unity-version-conditionals}{}\doxysubsection{\texorpdfstring{Unity version conditionals}{Unity version conditionals}}\label{md__a_g_e_n_t_s_unity-version-conditionals}
Version conditionals in this package guard real Unity API differences, verified by compiling against the editor in question, not by reading release notes. The ones present now\+:


\begin{DoxyItemize}
\item {\ttfamily UNITY\+\_\+2023\+\_\+2\+\_\+\+OR\+\_\+\+NEWER} in {\ttfamily \doxylink{_asset_8_path_8cs_source}{Asset.\+Path.\+cs}} and {\ttfamily \doxylink{_asset_8_file_8cs_source}{Asset.\+File.\+cs}}\+: {\ttfamily Asset\+Database.\+Asset\+Path\+Exists} and {\ttfamily Asset\+Database.\+Get\+Main\+Asset\+Type\+From\+GUID}.
\item {\ttfamily UNITY\+\_\+6000\+\_\+3\+\_\+\+OR\+\_\+\+NEWER}, {\ttfamily UNITY\+\_\+6000\+\_\+4\+\_\+\+OR\+\_\+\+NEWER} in {\ttfamily \doxylink{_asset_8_database_8cs_source}{Asset.\+Database.\+cs}}, {\ttfamily \doxylink{_asset_8_file_8cs_source}{Asset.\+File.\+cs}} and {\ttfamily Tests/\+Editor/\+Helper/\+Instantiate.\+cs}\+: Unity deprecated the integer instance ID APIs in 6000.\+3, deprecated {\ttfamily Object.\+Get\+Instance\+ID} and the {\ttfamily Int32}/{\ttfamily Entity\+Id} conversions in 6000.\+4, and turned all of them into compile errors in 6000.\+5. The public {\ttfamily Int32} parameter of {\ttfamily Asset.\+Database.\+Contains}, {\ttfamily Asset.\+File.\+Can\+Open\+In\+Editor} and {\ttfamily Asset.\+File.\+Open\+External} therefore becomes an {\ttfamily Entity\+Id} from 6000.\+4 on; 6000.\+3 keeps the {\ttfamily Int32} and converts internally.
\item {\ttfamily UNITY\+\_\+6000\+\_\+6\+\_\+\+OR\+\_\+\+NEWER} in {\ttfamily \doxylink{_asset_8_package_8cs_source}{Asset.\+Package.\+cs}}\+: {\ttfamily Asset\+Database.\+Import\+Package} and {\ttfamily Asset\+Database.\+Export\+Package} were deprecated in favour of {\ttfamily Unity\+Editor.\+Asset\+Package.\+Package}.
\end{DoxyItemize}

{\ttfamily Asset.\+Sub\+Asset.\+Set\+Main} saves the asset between {\ttfamily Asset\+Database.\+Set\+Main\+Object} and the import it does afterwards. That save is load-\/bearing from Unity 6000.\+7 on, where importing without it re-\/reads the old main object from disk; do not remove it as redundant.

Two Unity type moves have no conditional and must not grow one\+: the {\ttfamily GUID} struct is declared in {\ttfamily Unity\+Editor} up to Unity 6000.\+3 and in {\ttfamily Unity\+Engine} from 6000.\+4 on, and no Unity version declares it in both. The files that use {\ttfamily GUID} therefore import both namespaces and let the compiler resolve it. Removing either {\ttfamily using} breaks one half of the supported range.\hypertarget{md__a_g_e_n_t_s_maintaining-this-file}{}\doxysubsection{\texorpdfstring{Maintaining this file}{Maintaining this file}}\label{md__a_g_e_n_t_s_maintaining-this-file}
