\begin{DoxyItemize}
\item Minimum Unity version raised from 2021.\+3.\+3f1 to 2022.\+3.\+62f3. Every code path that only existed for Unity 2021.\+3 or 2022.\+1/2022.2 has been removed, in the package, the tests and the samples.
\item Fixed\+: the package did not compile in Unity 6000.\+4 or newer, because Unity moved the {\ttfamily GUID} type from the {\ttfamily Unity\+Editor} namespace to {\ttfamily Unity\+Engine}. The files that use {\ttfamily GUID} now import both namespaces; no Unity version declares the type in both, so the type resolves in either.
\item Fixed\+: the package did not compile in Unity 6000.\+5 or newer, because Unity removed the integer instance ID overloads of {\ttfamily Asset\+Database.\+Contains}, {\ttfamily Asset\+Database.\+Can\+Open\+Asset\+In\+Editor} and {\ttfamily Asset\+Database.\+Open\+Asset}, removed {\ttfamily Object.\+Get\+Instance\+ID}, and removed the conversions between {\ttfamily Int32} and {\ttfamily Entity\+Id}.
\item {\bfseries{API change in Unity 6000.\+4 and newer only\+:}} {\ttfamily Asset.\+Database.\+Contains}, {\ttfamily Asset.\+File.\+Can\+Open\+In\+Editor} and {\ttfamily Asset.\+File.\+Open\+External} take a {\ttfamily Unity\+Engine.\+Entity\+Id} instead of an {\ttfamily Int32} instance ID. In Unity 2022.\+3 up to and including 6000.\+3 they still take an {\ttfamily Int32} and are unchanged. What your code has to do on Unity 6000.\+4 and newer\+: replace {\ttfamily some\+Object.\+Get\+Instance\+ID()} with {\ttfamily some\+Object.\+Get\+Entity\+Id()} and pass that. Unity deprecated {\ttfamily Get\+Instance\+ID} in 6000.\+4 and removed it in 6000.\+5, so the integer these methods used to accept can no longer be obtained there. The overloads that take an asset {\ttfamily Object} are unchanged in every version and need no edit, as is the {\ttfamily Asset.\+Path} overload of {\ttfamily Asset.\+File.\+Open\+External}. {\ttfamily Asset.\+Database.\+Contains} and {\ttfamily Asset.\+File.\+Can\+Open\+In\+Editor} have no {\ttfamily Asset.\+Path} overload.
\item Fixed\+: the deprecation warnings Unity 6000.\+3 and 6000.\+4 raise for the integer instance ID APIs. On 6000.\+3 the {\ttfamily Int32} signatures are kept and the value is converted to {\ttfamily Entity\+Id} internally; from 6000.\+4 the {\ttfamily Int32} signatures are gone, which is what removes the last warnings.
\item Fixed\+: deprecation warnings in Unity 6000.\+6 and newer, where {\ttfamily Asset\+Database.\+Import\+Package} and {\ttfamily Asset\+Database.\+Export\+Package} are deprecated in favour of {\ttfamily Unity\+Editor.\+Asset\+Package.\+Package}.
\item {\bfseries{Added in Unity 6000.\+6 and newer only\+:}} the three {\ttfamily Asset.\+Package.\+Export} overloads and the {\ttfamily Asset().Export\+Package} instance method take an optional trailing {\ttfamily owner\+Org\+Id}. Unity uses it as the exported package\textquotesingle{}s signing organization; the Organization ID is in the Unity Cloud dashboard under Administration =\texorpdfstring{$>$}{>} Settings. Omitting it preserves the previous behaviour exactly. The parameter does not exist in Unity 2022.\+3 up to and including 6000.\+5, because Unity cannot honour it there. Existing calls compile unchanged in every version.
\item Fixed\+: {\ttfamily Asset.\+Sub\+Asset.\+Set\+Main} and the {\ttfamily Asset.\+Main\+Object} setter did not take effect in Unity 6000.\+7. {\ttfamily Asset\+Database.\+Set\+Main\+Object} only records which object should become the main one on the next import; it does not write the asset file. From Unity 6000.\+7 on, the import that follows re-\/reads the old main object from disk and the change is lost. The asset is now saved between the two calls, which is correct in every supported version.
\item Removed an unused {\ttfamily using NUnit.\+Framework;} from {\ttfamily \doxylink{_asset_8_status_8cs_source}{Editor/\+Asset.\+Status.\+cs}}. The directive emitted no assembly reference; it only resolved because {\ttfamily Editor/\+Code\+Smile\+Editor.\+Asset\+Database.\+asmdef} sets {\ttfamily override\+References} to false, so Unity auto-\/references every precompiled assembly. Removing it means the package no longer fails to compile in a project without the test framework.
